# Единый снимок рабочего состояния ME302KL

Составлен 12 ноября 2026 (Europe/Sofia). Это исходная спецификация будущего объединённого патча, **не новый установщик и не полный backup**. Планшет при составлении не виден по ADB: состояние сведено по последним успешным проверкам, без новой live-сверки. Перед сборкой релиза требуется повторно подключить планшет и сравнить фактические файлы, права, настройки и boot.

[Машиночитаемый снимок](../snapshots/2026-11-12-working-state.json) содержит точные SHA-256, 12 файлов существующего пакета, допустимые исходные версии, права/SELinux labels, зависимости, GPS symlink, ожидаемые настройки и список исключённых экспериментов. Значения из manifest — ожидаемые, а не результат нового чтения планшета.

## Поддерживаемая база

ASUS ME302KL / duma, Android 10, `17.1-20230306-UNOFFICIAL-duma`. Проверено на одном планшете. Не переносить бинарные изменения автоматически на Android 13 или другую сборку. Нынешний boot SHA-256 по последней проверке: `d2cacd5c413e13a17489b7161062f2e9edbe53c3044c33368380d66df80b8cfc`.

## Что не включаем

Экспериментальные thermal HAL/startup изменения, PNO/atomic-packet/WCNSS эксперименты, официальный VIDC-комплект, input-port patch и увеличенный MFC heap. Эти изменения откатаны. Secure AVC с ними прошёл lifecycle, но аппаратный DRM playback не доказан; L1 блокируется несовместимостью OEMCrypto. Старый thermal-control service сохранён, современное Android thermal reporting не восстановлено. HDMI не проверен с кабелем, прежний crash остаётся открытой задачей.

Не упаковывать приложения, аккаунты, userdata, IMEI/EFS, DRM certificates/keybox/provisioning storage, Wi-Fi credentials, raw logs или rooted-debugging preference владельца. Исторические e2fsck/очистка кеша — обслуживание конкретного устройства, не файлы исправления; не выполнять очистку пользовательских данных как часть общего патча.

## Существующий пакет и недостающая часть

Приватный `ME302KL-LOS17.1-working-repairs-2026-11-12.zip`, SHA-256 `5ed9cc87d639bd200427b14c5655c56a2a01169447c3f522e26f5b456462f96f`, содержит 12 системных файлов и этап configure. При составлении снимка на ПК проверены все 12 payload hashes и совпадение manifest с исходным manifest. Сам ZIP не публикуется; полный ROM/vendor binaries и backups остаются приватными. [Нынешние инструкции](repair-bundle-install.txt).

В этом пакете **нет boot image/watchdog repair и нет Widevine provisioning**. Он не является полным воспроизведением нынешнего состояния. Его старые ограничения по DRM следует читать вместе с поздней [успешной регистрацией L3](widevine-provisioning-2026-11-12.md).

Будущий единый комплект должен объединять три стадии: системные ремонты, проверенное изменение boot и отдельную процедуру регистрации L3. Это может быть один комплект с несколькими этапами; требование «один ZIP одним нажатием» пока не реализовано. Для регистрации нужен Google endpoint и при необходимости согласие на отправку штатного подписанного запроса. Сертификаты владельца переносить нельзя.

## Критерии готовности объединённого пакета

1. Повторная live-сверка с этим снимком; несовпадения документировать, не заменять ожидаемые хеши молча.
2. Проверка точной ROM, исходных файлов, boot и partition mapping; отказ при неизвестном исходном состоянии. Предпочтительно воспроизводимый hash-locked patch, не чужой полный boot.
3. PC backup затрагиваемых файлов/настроек и boot, readback после записи, независимый rollback каждого этапа. Существующий backup пакета не является полным backup устройства.
4. Одна согласованная версия установщика, manifest, инструкций и журнала результата. Повторный запуск на отремонтированном устройстве не меняет уже правильные файлы. Не смешивать со старыми скриптами, отключающими HFP.
5. Boot, rotation, Wi-Fi/recovery, Bluetooth speech, GPS outdoors и L3 session проверены после установки. Ошибки лицензирования не маскируются и не откатывают успешные несвязанные ремонты.
6. Проверка восстановления на той же чистой ROM и отката, когда будет согласован такой эксперимент. Нынешний рабочий планшет не сбрасывать ради подготовки документации.

Снимок обновляется после следующего принятого ремонта; экспериментальные результаты добавляются отдельно, пока их постоянная установка и проверки не подтверждены.
