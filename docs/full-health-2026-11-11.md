# Общее состояние планшета: диагностика 11 ноября 2026

**Позднейшее обслуживание:** [Google DeviceConfig исправлен, thermal-кандидат удалён](software-gaps-2026-11-11.md). Совместная установка привела к остановке загрузки с kernel thermal NULL-pointer; после отката Android загружается, прежние ремонты сохранены. Ниже — исходный аудит до этих изменений.

**Последующая проверка system выполнена:** [offline e2fsck](system-fsck-2026-11-11.md) не нашёл структурных ошибок; чистая метка восстановлена, после загрузки Android state clean. Ниже сохранён исходный результат аудита до этого обслуживания.

**Итог:** планшет работоспособен и в этой короткой проверке стабилен. Текущих падений, ANR, kernel panic, OOM или ошибок ввода-вывода накопителя не найдено. При этом есть незавершённые вопросы обслуживания файловой системы, износ батареи и несколько программных несовместимостей. Это оценка работающей системы, а не сертификат исправности всех физических компонентов.

Проверка началась примерно через шесть минут после предыдущей тестовой перезагрузки. В рамках самого аудита планшет не перезагружался, файлы ROM и настройки не менялись, приложения не устанавливались/удалялись. Собраны kernel/all-buffer logcat, crash buffer, DropBox, состояния служб, память, накопитель, superblock, питание, температуры, Wi-Fi/сеть, Bluetooth, sensors, location, camera/audio/display/input, WebView и хеши ремонтов. Сырые материалы сохранены на ПК.

Память старого ядра учитывается неточно: `dumpsys meminfo` показывает отрицательный Lost RAM. Поэтому его отдельную цифру Free RAM нельзя считать точным аппаратным измерением. Низкий MemFree сам по себе не проблема: значительная часть RAM занята освобождаемыми кешами.

## 1. System помечен как not clean: нужен отдельный offline check

`tune2fs -l` и прямое чтение superblock показали:

- System сейчас смонтирован **read-only**.
- `Filesystem state: not clean`, raw state 0.
- Записанный error count — **0**, `last_orphan_inode` — **0**.
- У этого system-раздела нет журнала; в текущем kernel-журнале нет EXT4/I/O ошибок.
- Userdata и cache имеют state clean. Их `needs_recovery` при активном mounted RW journal — обычный рабочий флаг, не найденная поломка.

Метка system могла остаться после недавних remount/замен файлов и перезагрузок; точная причина в этом аудите не установлена. **Она не равна доказанной порче файлов**, но и нулевой счётчик ошибок не заменяет полный check. Следующее полезное обслуживание — проверка system в recovery, когда раздел не используется. На смонтированной рабочей системе fsck не запускался; никаких изменений superblock не делалось.

Показатели eMMC lifetime/pre-EOL этим ядром не предоставлены. Поэтому из отсутствия I/O ошибок нельзя получить оценку оставшегося ресурса flash. Прочитанная строка даты eMMC выглядит ненадёжной и не использована для оценки возраста.

## 2. Батарея: вероятен существенный износ

Gauge сообщает full-charge capacity **3576 mAh** при design **6760 mAh**, то есть около **52.9%** проектной ёмкости; cycle count **1087**. Температура батареи около **29.8 °C**, health flag — Good. Низкая оценка ёмкости и отсутствие флага неисправности могут сосуществовать: износ не равен аварийному состоянию.

Это оценка контроллера, не результат полного контролируемого разряда; значения FCC могут меняться. Единицы/смысл `current_now` и `charge_counter` у старого драйвера не использованы для расчёта расхода. Диагностика выполнялась с USB и сама создаёт нагрузку. Конкретное время автономной работы и экономию от sensor v2 нужно измерять отдельно.

## 3. Тепловой стек: framework reporting отсутствует, старые механизмы присутствуют

`dumpsys thermalservice` показывает `HAL Ready: false`, кеш температур framework пуст. Это подтверждённый пробел Android thermal reporting.

Одновременно `thermald` работает, `/system/etc/thermald.conf` содержит CPU/shutdown actions, а kernel `msm_thermal` предоставляет пределы температуры/частот. Датчик `tsens_tz_sensor0` показал raw 38, батарея около 30 °C; сигналов перегрева не найдено. Для части неактивных thermal zones чтение возвращает Invalid argument. Отсутствие framework HAL **не доказывает отсутствие всей тепловой защиты**. Реальная реакция на нагрев и throttling под нагрузкой не испытывалась; защитные механизмы не отключались.

## 4. Google Play services: отклонённые DeviceConfig updates

В захваченном журнале найдены **12 отдельных** `PlatformConfigurator updateFromConfigurations failed` в одном коротком burst. 336 строк этого тега — вместе со stack traces, не 336 независимых отказов и не доказательство непрерывного цикла.

Причина в сообщениях: отказ `android.permission.WRITE_DEVICE_CONFIG`. Обновлённый и исходный GMS запрашивают это право, но в показанных granted permissions оно отсутствует. В этой ROM protection level — `signature|verifier|configurator`, поэтому простая выдача произвольного privileged/runtime permission не является обоснованным ремонтом. Следующее программное исследование при необходимости — совместимость/назначение configurator и Google-пакетов. Права в этом аудите не выдавались. Пользовательский сбой из-за этих отказов отдельно не воспроизведён.

## 5. Wi-Fi: работает, быстрый boot autojoin не подтверждён

В текущем boot kernel есть старые сообщения offload failure на ранних disconnected этапах. Они не означают, что ранее выполненный тест sleep/wake провалился. [Отдельная reboot-проверка](wifi-autoconnect-2026-11-11.md) подтвердила eventual auto-connect без выбора сети, примерно через четыре минуты и после wake/unlock. Выбор другой сохранённой сети перед возвратом к рабочей остаётся кандидатом для дальнейшего исследования. В этом аудите соединение и ping/DNS работают.

## Как интерпретированы остальные журналы

- DropBox текущего boot содержит StrictMode/WTF, но не зарегистрированный crash/ANR. Они разобраны отдельно от фатальных сбоев. `SYSTEM_LAST_KMSG` после обычной перезагрузки сам по себе не доказывает kernel panic.
- WTF включают TrustManagerService, SystemConfig в phone provider и KeyguardBouncer; процесс не обязан завершаться от такой записи. Наличие общего phone provider не означает включённый сотовый RIL.
- Missing optional property files, дублирующий legacy RIL service и отсутствующие новые ioctl старого ядра — совместимость/логирование, без нового подтверждённого отказа функции.
- Попытка mount `/cache` как f2fs с invalid magic — неуспешный альтернативный вариант; фактически cache смонтирован ext4, а не доказанно повреждён.
- WifiHAL не поддерживает часть новых statistics/packet-monitoring API; это не равно отказу передачи данных.
- MediaScanner снова отвергает 17 FLAC assets. Ранее у первого проверенного файла не было сигнатуры FLAC; файлы не менялись, дефект декодера не установлен.
- В текущем kernel-журнале нет новых checksum/malformed packet ошибок тачскрина. Это не заменяет повторную физическую проверку панели.

## Безопасность и ограничения

Установленный security patch level — **2023-02-05**, SELinux — **Permissive**, rooted debugging/ADB оставлен включённым по просьбе владельца; `/data` сообщает unencrypted. Наши точечные ремонты не обновляют базу безопасности Android. Эти настройки в аудите не менялись. Проверка не включала сканирование на вредоносные приложения или подтверждение отсутствия уязвимостей.

Практический порядок следующих действий: **offline check system**, затем при необходимости исследование GMS DeviceConfig и thermal reporting; батарею оценивать отдельным длительным наблюдением. Новых ROM-патчей по одному наличию сообщений в журнале не установлено.
