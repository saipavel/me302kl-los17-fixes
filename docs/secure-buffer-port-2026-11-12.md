# Secure AVC: исправление переключателя входных буферов

12 ноября 2026. Экспериментальная правка устранила воспроизводимое падение `media.codec` при выделении защищённых входных буферов. Полноценное DRM-воспроизведение ещё не подтверждено. Правка **не оставлена установленной**, исходные библиотека и firmware восстановлены.

## Причина и правка

После временной установки полного официального VIDC-комплекта открытие и configure проходят. Вызов start с исходной `libOmxVdec.so` приводит к SIGSEGV: HIDL сериализует значение `0xb` как указатель на `native_handle`, обращаясь к адресу `0xf`.

Подробный журнал показал последовательность `enableNativeBuffers`: вход, native handle = 1; выход, native handle = 0; выход, graphic = 1. Дизассемблирование установленной библиотеки подтверждает, что обработчик `allocateNativeHandle` с индексом `0x7f00005d` записывает один общий флаг по смещению `0xa09d`, не учитывая номер порта. Настройка выхода сбрасывает флаг, который нужен входу. Выделение входного буфера тогда возвращает файловый дескриптор вместо структуры native handle, хотя framework считает новый формат включённым.

Экспериментальный патч учитывает `nPortIndex`: только порт 0 меняет этот флаг, для других портов операция завершается без изменения флага. Существующий код библиотеки сам создаёт native handle и управляет его жизненным циклом. Проверки DRM и защищённого вывода не отключаются.

[Сборщик патча](../experiments/secure-codec-open/patch_input_port.py) принимает только библиотеку с SHA-256 `4437d8b36695ffd0e528b22eb4f305fd2836356ed2fbff8b4a783faca0fcf476`. Он использует 28 байт проверенного нулевого заполнения, расширяет RX-сегмент в пределах промежутка до следующего сегмента и проверяет адреса переходов дизассемблером. Это инструмент исследования, не установщик и не универсальная правка для Android 13.

## Проверка

- Без патча: два запуска воспроизвели падение службы при start. Init восстановил службу.
- Первая сборка патча содержала ошибочный адрес условного перехода, вызванный кодированием инструкции ассемблером. Это привело к отдельному экспериментальному падению. Сборка исправлена: локальная метка и проверка получившихся переходов. Первая сборка не публикуется как рабочая.
- Исправленный участок прошёл восемь проверок в ARM-эмуляторе: оба порта, включение/выключение и оба исходных значения флага.
- С исправленным патчем и официальным firmware создаются два защищённых входных буфера с настоящими native handles. Прежнего падения службы в этом запуске нет.
- Start затем возвращает ошибку: `SurfaceUtils` сообщает, что потребитель временной SurfaceTexture не поддерживает protected buffers. Это ограничение тестового вывода, а не доказательство нового дефекта планшета. Helper использует null MediaCrypto, не получает лицензию и не декодирует кадры.
- Release завершился самостоятельно; полное время около 40,5 секунды. Задержки legacy Binder остаются.
- После отката обычный AVC прошёл create/configure/start/stop/release за 222 мс; это проверка жизненного цикла, не воспроизведения кадров. PIL refcount равен 0.

Библиотека и пять файлов firmware подключались временными bind mounts. При откате библиотеку сначала пришлось освободить остановкой службы, затем снять mount и запустить службу заново. Исходный SHA-256 проверен. Диагностическое свойство возвращено к пустому значению, временные файлы теста удалены. Crash logs сохранены: они содержат перечисленные экспериментальные падения. Нельзя описывать этот этап как «чистый crash buffer».

## Следующий рубеж

Нужен тестовый экран с подходящим защищённым Surface/SurfaceView, затем start/stop, повторные открытия и настоящее лицензированное DRM-воспроизведение. Отдельно требуется адаптация старых Binder-вызовов: media.codec использует vndbinder, тогда как activity и display.qservice доступны через системный Binder; простой перенос службы в другое пространство ещё не гарантирует совместимость старых протоколов. До этих проверок secure AVC остаётся скрытым в XML, рабочий пакет ремонтов не меняется.
