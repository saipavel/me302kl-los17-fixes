# GPS: управление питанием через переключатель Location

11 ноября 2026 установлен небольшой адаптер legacy GPS HAL для текущего ME302KL / LineageOS 17.1 20230306. Он связывает питание общего модема с уже существующим жизненным циклом GPS в Android. Постоянный фоновый процесс и сценарий «включить модем навсегда при загрузке» не устанавливались.

## Поведение

- Включение Location вызывает GPS `init`: адаптер проверяет DMS-режим модема и переводит его в ONLINE (0), затем вызывает исходный GPS HAL.
- Реальный запрос приложения вызывает GPS `start`: состояние ONLINE проверяется ещё раз. Запуск, остановка и расчёт спутниковой позиции остаются в прежнем драйвере.
- Выключение Location вызывает исходный `cleanup`, затем перевод в LOW_POWER (1).
- На старте Android делает короткий цикл `init`/`cleanup` даже при выключенной Location. Поэтому краткое включение общего модема в начале загрузки возможно; после этого сохраняется состояние Location. Это предусмотренное поведение Android для регистрации GNSS callback, а не постоянно работающая навигация.
- При исходном DMS SHUTTING_DOWN (5), наблюдавшемся после загрузки без RIL, используется последовательность LOW_POWER → ONLINE. Неизвестные режимы не изменяются.

При включённой Location общий модем может оставаться ONLINE даже без приложения навигации. Сам приёмник запускается обычными запросами Android. Остановка приложения не равна выключению Location. Длительный расход батареи ещё не измерен.

Режим полёта сам по себе не запрещает спутниковую навигацию Android; управление GPS здесь следует Location. Сотовые данные и телефонные службы не включаются. Адаптер не меняет настройку режима полёта.

## Установленные файлы и отключение

| Путь | Назначение |
|---|---|
| `/vendor/lib/hw/gps.msm8960.so` | Новый адаптер, собственный код проекта |
| `/vendor/lib/hw/gps.msm8960.base.so` | Неизменённый восстановленный vendor HAL, 30432 байта |
| `persist.me302kl.gps_power_control=1` | Включает управление питанием |

Исходный HAL SHA-256: `d251c672b0baf911aff7e57086bcab2b349a3040d370d99e30019dd3ea157178`. Адаптер SHA-256: `0dc65723709bac4b8574bcedb9285a72405f6ee7d4d7f26965d5405667e70016`, размер 18744 байта. Текущие исправления NMEA/HIDL, датчиков и Bluetooth не заменялись.

Питание меняется только если **обе** настройки `persist.me302kl.gps_power_control=1` и `persist.me302kl.cellular_disabled=1`. Для отключения сначала выключите Location, дождитесь LOW_POWER, затем выполните `adb shell setprop persist.me302kl.gps_power_control 0`. Адаптер после этого передаёт вызовы старому HAL без управления модемом. Сохраняется зависимость от ручного включения модема, как до этого изменения.

Полный откат: при выключенной Location проверить SHA-256 файла `.base.so`, выключить свойство, перемонтировать `/` в запись и скопировать `.base.so` поверх `gps.msm8960.so` с сохранением владельца `root:root`, прав `0644` и контекста `u:object_r:vendor_file:s0`. Проверить исходный SHA-256, вернуть `/` в режим чтения и полностью перезагрузить планшет. Файл `.base.so` можно удалить после подтверждения отката. **Простого копирования поверх библиотеки недостаточно для уже работающего `system_server`; нужна перезагрузка.**

## Проверки и ограничения

- Реальные DMS-запросы от UID 1000, с группами radio/gps: LOW_POWER → ONLINE, повторный ONLINE без смены состояния, ONLINE → LOW_POWER.
- Парсер ответов: успешные, ошибочные, отсутствующие, повторные и усечённые TLV; обязательный QMI result проверяется перед принятием режима. Подтверждение смены режима опрашивается ограниченное число раз: успешный ответ на команду не означает мгновенного перехода.
- После полной перезагрузки с выключенной Location: режим 5 корректно обработан; после начального цикла Android модем вернулся в 1.
- Два последовательных включения/выключения Location: режимы 0/1 подтверждены независимыми DMS-запросами.
- GPSTest после перезагрузки: `mStarted=true`, модем ONLINE, ручное включение модема не использовалось. Выключение Location вернуло LOW_POWER.
- Вторая полная перезагрузка с включённой Location: после загрузки ONLINE; последующее выключение Location вернуло LOW_POWER. Crash buffer пуст, `sensors`, `qmuxd`, `kickstart` работают; `ril-daemon`, `bridgemgrd`, `netmgrd` остановлены. Wi-Fi и Bluetooth включены, три ранее установленных бинарных ремонта сохранили хеши.

Краткая проверка без координат: [gps-power-2026-11-11.json](../evidence/gps-power-2026-11-11.json). В конце Location возвращена в исходное выключенное состояние, таймаут экрана — 5 минут. Rooted debugging оставлен включённым по просьбе владельца.

После проверки 56 временных файлов диагностики/изолированных тестов сохранены в приватный архив на ПК; SHA-256 каждого файла сверен с планшетом перед удалением обоих тестовых каталогов. `/data/local/tmp` пуст. GPSTest оставлен для повторного уличного теста, Maps и Audio Recorder сохранены. `.base.so` — необходимая рабочая зависимость адаптера, а не лишний бэкап.

В первом сценарии проверки приложения было неверное имя Activity; запуска GPS он не проверил. После получения правильного компонента `com.android.gpstest.ui.MainActivity` тест повторён и прошёл. Это ошибка сценария, а не исправление драйвера. Уличные координаты за 62 секунды были получены **до** установки адаптера. После установки владелец отдельно подтвердил получение координат 11 ноября: «tested, got location fix». Время до фикса, точность и условия этого повторного теста не сообщались; новые сырые измерения не снимались.

Проверено на текущей **Permissive** ROM; адаптер не меняет SELinux. Для Enforcing нужны отдельные проверки политики. На других модемах, прошивках и Android 13 не проверено. Если DMS недоступен или команда не подтверждена, `init/start` возвращают ошибку; постоянного цикла повторных запусков нет. Восстановление после неожиданного перезапуска модема в середине навигации отдельно не проверялось.

## Исходники и сборка

[gps_power.c](../tools/gps-power/gps_power.c) содержит ARM32 ABI-адаптер, ограниченные DMS-команды чтения/изменения operating mode и проверку результатов. NV, assistance, SIM и RIL он не настраивает. Позиции не записывает. Короткие сообщения появляются под тегом `ME302KL-GpsPower` только при вызовах питания/инициализации.

[build.py](../tools/gps-power/build.py) воспроизводит использованную команду сборки Zig 0.13.0 с Krait/softfp. Нужны приватные динамические библиотеки для линковки `libc.so`, `libdl.so`, `liblog.so` от планшета. Исходный vendor HAL и эти библиотеки не публикуются. Установка требует проверки исходного хеша, добавления `.base.so` и полной перезагрузки; старый основной PowerShell-сценарий этого не делает.

Повторная сборка этим сценарием в том же рабочем каталоге дала точный SHA-256 установленного адаптера. Пути исходников входят в отладочные сведения; сборка из другого расположения может иметь другой хеш.

Жизненный цикл проверен по AOSP `GnssLocationProvider.handleEnable/handleDisable/setupNativeGnssService` и `Gnss.cpp`; ARM32 структуры модуля/устройства проверены по существующей библиотеке и родственным исходникам Qualcomm. Размер исходного `GpsInterface` на устройстве — 40 байт, остальные функции и extensions передаются без изменения.
