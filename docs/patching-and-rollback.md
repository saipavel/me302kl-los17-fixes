# Воспроизведение патчей и откат

**Обновление датчиков 11 ноября:** ниже сохранены инструкции для первого набора. Для текущего ремонта сна нужен `--manifest patches/2026-11-11.json`: вариант `sensors-logmask-v2` обновляет первый ремонт, `sensors-v2-from-original` работает с исходным непочиненным daemon. [Проверки, хеши и команды](sensor-sleep-fix-2026-11-11.md). Без `--manifest` по-прежнему выбран исторический набор 10 ноября.

Для **точных файлов** `lineage-17.1-20230306-UNOFFICIAL-duma`. Python 3, без дополнительных пакетов. Инструмент ниже работает только с локальными файлами и ничего не устанавливает на устройство.

```powershell
python tools/patch_rom.py --list
adb pull /vendor/bin/sensors.qcom sensors.input
python tools/patch_rom.py sensors sensors.input sensors.patched
```

Если файл уже исправлен, восстановить оригинал на ПК можно обратной дельтой:

```powershell
python tools/patch_rom.py --reverse sensors sensors.input sensors.original
```

Аналогично доступны `bluetooth`, `gnss-nmea`, `gps-assistance-config`, `wifi-only-config`. Последние два — конфигурация, не решение GPS/SIM. Исходный и итоговый SHA-256, размеры, путь на устройстве и изменяемые байты находятся в [манифесте](../patches/2026-11-10.json). При другом хеше нужно остановиться и заново исследовать файл; обходить проверку нельзя.

## Установка подготовленного файла

На проверенном устройстве использовались Rooted debugging, `adb root` и временный `mount -o remount,rw /`. Это system-as-root; `/vendor` указывает на `/system/vendor`. Права записи после установки возвращались в read-only. TWRP или перепрошивка всей ROM для этих ремонтов не требовались.

1. Скопировать исходный файл и сохранить проверенный бэкап **на ПК**.
2. Сгенерировать кандидата с проверкой хешей. Передавать его сначала в `/data/local/tmp/`, не прямо поверх работающей библиотеки.
3. Сверить SHA-256 кандидата и ещё раз исходного файла на устройстве.
4. Остановить затрагиваемую службу: датчики — `stop sensors`; Bluetooth — `svc bluetooth disable`, затем `am force-stop com.android.bluetooth`; при работе с GNSS завершить GPS-приложения и временно выключить location. Учитывать имена служб именно своей сборки.
5. После remount создать **новый соседний файл**, установить владельца/режим/SELinux label и проверить хеш; затем заменить целевой файл через `mv`. Не перезаписывать содержимое mmap-библиотеки работающего процесса.
6. `sync`, возврат system в read-only, **полная перезагрузка**, повторная проверка хеша и функции. Если remount в read-only сообщает busy, не писать, что он успешен: после перезагрузки отдельно проверить `/proc/mounts`.

| Файл | Владелец | Режим | SELinux label |
|---|---|---|---|
| `sensors.qcom` | `root:shell` | `0755` | `u:object_r:sensors_exec:s0` — сверить с исходным файлом своего устройства |
| `libbluetooth.so` | `root:root` | `0644` | `u:object_r:system_lib_file:s0` |
| `android.hardware.gnss@1.0-impl.so` | `root:root` | `0644` | `u:object_r:vendor_file:s0` |
| `gps_debug.conf` | `root:root` | `0644` | Сохранить исходный контекст |
| `/vendor/build.prop` | `root:root` | `0600` | `u:object_r:vendor_file:s0` |

Для действующего Bluetooth-ремонта требуется `adb shell settings put global bluetooth_disabled_profiles 0`. Старый `me302kl-los17-fix.ps1` отключает HFP: повторно запускать его Bluetooth-часть после этого ремонта не следует. Новые патчи в старый автоматический сценарий не встроены.

## Узкий откат

- **Датчики / Bluetooth / NMEA:** получить текущий исправленный файл, выполнить соответствующий `--reverse`, проверить хеш оригинала из манифеста и установить тем же способом. Для отката Bluetooth к прежнему обходу также вернуть `bluetooth_disabled_profiles=2`.
- **Framework GPS-конфигурация:** `--reverse gps-assistance-config` возвращает исходный `gps_debug.conf`, без добавленных серверов.
- **Восстановленные GPS-файлы:** если нужно вернуть исходное отсутствие драйвера, сначала сверить хеши из отчёта, затем удалить только `/vendor/lib/hw/gps.msm8960.so`, `/vendor/lib/libgps.utils.so` и добавленную ссылку `/system/etc/gps.conf` (проверив её точную цель). Эти файлы не являются заменой прошивки модема.
- **Сотовое отключение:** обратной дельтой `wifi-only-config` вернуть исходный `/vendor/build.prop`; установить `persist.me302kl.cellular_disabled=0`; удалить только `/vendor/etc/init/me302kl-cellular-disabled.rc`; вернуть `pm default-state --user 0` для `com.android.phone`, `com.android.mms.service`, `com.google.android.carriersetup`; восстановить `airplane_mode_radios=cell,bluetooth,wifi,nfc,wimax`; выполнить полную перезагрузку. `mobile_data` и `data_roaming` остаются 0, если пользователь сам не решит включить их. Сотовая связь этим не считается исправленной.

После очистки временных файлов сохранённые когда-то рядом с библиотеками `.pre-*` могут отсутствовать. Обратные дельты не требуют этих файлов; частные копии оригиналов и полный TWRP-бэкап есть на ПК владельца. Для возврата TWRP-бэкапа сначала скопировать его обратно на планшет, сохранив все `.win*` и `.md5`. Не восстанавливать EFS/радио/bootloader для обычного отката системной библиотеки.

Исходные сборки целиком не выкладываются. Эти бинарные дельты не подходят автоматически для LineageOS другой даты или Android 13. Подробности испытаний и ограничения — в [отчёте](2026-11-10-repairs.md).
