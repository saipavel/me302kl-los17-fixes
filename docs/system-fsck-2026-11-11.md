# System filesystem: offline check и чистая метка, 11 ноября 2026

**Проверка завершена: структурных ошибок не найдено.** Оставшаяся метка `not clean` сброшена штатным e2fsck, повторная проверка прошла, после загрузки Android раздел сохранил состояние **clean**. Исправления датчиков, Bluetooth и GPS сохранили хеши.

## Подготовка и область проверки

Полный проверенный бэкап 10 ноября остаётся на ПК. Дополнительно перед работой сохранён свежий raw image system, включающий все текущие ремонты: **1610612736 байт (1.5 GiB)**. Копия снята с read-only раздела; SHA-256 всего файла на ПК совпал с SHA-256 блочного устройства. Образ остаётся приватным, на планшет не копировался.

Планшет загружен в уже установленный **TWRP 3.1.0-1 SevenMaxs**. Target system проверен как `/dev/block/mmcblk0p22`, major:minor `179:22`. До проверки он не был смонтирован; отсутствие mount проверялось по `/proc/self/mountinfo` перед каждым запуском и после. Android в это время не работал. Использован штатный recovery **e2fsck 1.42.9**; неподдерживаемых filesystem features он не сообщил.

Проверялся только system. Userdata/cache не ремонтировались; ROM-файлы не заменялись, boot/kernel/modem не прошивались.

## Результаты по этапам

| Этап | Команда в recovery при unmounted system | Результат |
|---|---|---|
| Первичная проверка без записи | `e2fsck -f -n /dev/block/mmcblk0p22` | Все пять passes прошли, exit 0; superblock побайтово не изменился; state остался 0 |
| Штатное завершение/исправление состояния | `e2fsck -f -p /dev/block/mmcblk0p22` | Exit 1 — метаданные изменены; state стал 1 (clean); file/directory corrections не сообщались |
| Повторная проверка без записи | `e2fsck -f -n /dev/block/mmcblk0p22` | Все пять passes прошли, exit 0; superblock после неё не изменился |
| После загрузки Android | Чтение superblock, `tune2fs -l`, mount и хешей | State 1, error count 0, system read-only, восемь хешей ремонтов совпали |

Пять passes: inodes/blocks/sizes, directory structure, directory connectivity, reference counts, group summary information. До и после одинаковые счётчики: **3879/98304 files**, **310708/393216 blocks**, 0.4% non-contiguous. Error count и last orphan inode равны нулю.

`-p` используется для штатных безопасных автоматических исправлений, а не безусловного согласия на все запросы. Он запускался только после успешного read-only прохода, проверки отсутствия mount и готовности проверенного rollback image. Неожиданный код результата остановил бы продолжение. Здесь checker не сообщил о ремонте файлов, каталогов, ссылок или bitmap; наблюдаемое исправление — нормализация состояния filesystem. Exit 1 на этом этапе не означает неуспешное завершение; следующий read-only проход вернул 0.

Команды выше относятся к проверенному устройству и **не предназначены для запуска на смонтированном Android system**. Для другого устройства mapping разделов нужно устанавливать отдельно.

## Что означает исходная метка

В исходном superblock был state 0 (`not clean`), при нулевых error count и last orphan inode. Offline check не подтвердил порчу структуры. Метка могла сохраниться после предыдущих remount/системных изменений и перезапусков; точный момент и причина не установлены. Наличие такой метки само по себе не доказывало неисправность eMMC.

Этот тест проверяет структуру файловой системы, а не каждый байт содержимого всех ROM-файлов или остаточный ресурс flash. Для установленных ремонтов дополнительно проверены SHA-256; полный дооперационный raw image сохранён на ПК.
